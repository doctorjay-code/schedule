# 🛡️ 에이전트 소통 및 개발 행동 지침 (Agent Communication & Dev Rules)

모든 AI 에이전트는 사용자와 대화하거나 작업을 진행할 때 **반드시 아래 4대 원칙을 철저히 준수**해야 합니다.

---

## 1. ✋ "선 제시 및 동의 구하기, 즉각 코딩 착수 금지" (가장 중요)
* 사용자가 **"이거 이상하다", "이렇게 하면 어떨까?", 질문이나 피드백**을 했을 때:
  1. 바로 코드를 수정하거나 파일 수정을 먼저 진행하지 않습니다.
  2. 무엇이 원인/문제인지, 혹은 기능을 어떻게 구현/개선할 것인지에 대한 **구체적인 원인 분석 및 해결 방안(플랜)을 명확히 정리하여 먼저 제시**합니다.
  3. **"이렇게 수정/진행할까요?"**라고 사용자에게 물어보고, **사용자의 명시적 동의/승인(예: "응", "고쳐줘", "진행해")을 받은 후에만** 실제 코드 작업에 착수합니다.

---

## 2. 🔍 오류 원인은 "추측" 금지, "실제 로그/기록/코드 데이터"로 팩트 확인
* 사용자가 오류를 제기했을 때 절대 "이럴 것입니다" 식의 **심증이나 추측으로 성급하게 답변하지 않습니다.**
* **실제 근거 기반 확인 절차:**
  1. 관련 소스 코드 전체 흐름 및 데이터 타입(숫자 vs UUID 문자열 등) 확인
  2. 실제 호출 스택, 브라우저 콘솔 로그, DB(Supabase) 실제 데이터 값 대조
  3. 필요 시 스크립트를 작성하여 실제 데이터와 함수를 실행/재현해보고 **명확한 기술적 근거와 팩트를 확보한 뒤** 사용자에게 설명합니다.

---

## 3. 🧪 수정 후 "반드시 실제 검증 및 테스트" 수행 후 보고
* 사용자 동의 후 코드를 수정한 뒤, "수정했습니다"로 끝내지 않고 **수정된 내용이 정상 동작하는지 테스트**를 거칩니다.
* **필수 검증 단계:**
  1. 전체 모듈 문법 및 브라우저 환경 로드 무결성 테스트 실행
  2. 수정된 함수에 실제 데이터 샘플을 넣어 엣지 케이스까지 의도대로 동작하는지 검증
  3. 검증 결과가 100% 정상 통과된 것을 확인한 후에 사용자에게 완료 보고

---

## 4. 🚀 배포 및 캐시 갱신 자동화 준수
* 수정 완료 후 반드시 `js/version.js`의 `APP_BUILD_TIME`과 `index.html`의 `style.css?v=` 타임스탬프 버전을 올려 캐시 문제를 방지하고, Git 커밋/푸시까지 마무리합니다.
